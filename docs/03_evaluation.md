# 03 - Evaluation

Script: `python scripts/evaluate_fidelity.py` → prints a table and writes `reports/fidelity.json`.
Tests: `python -m unittest discover -s tests -t .` (89 tests, 1 skipped). The API test class is skipped when FastAPI
and httpx are not installed, which was the case in the environment where this was built, so the API
endpoints themselves have not been exercised; running the tests after `pip install -r requirements.txt`
includes them. Awkward inputs are covered separately by `python scripts/corner_cases.py` (49 cases, see [chapter 10](10_corner_cases_and_troubleshooting.md)).

## What is measured

For each sample file the true content is known (`data/samples/expected/*.json`):

| Measure | Meaning |
|---|---|
| Word recall | Share of the source's words present in the Markdown (low = text lost) |
| Word precision | Share of Markdown words that belong to the source (low = junk, duplicates, garbling) |
| Order | Longest in-order share of paragraph anchors (low = wrong reading order, e.g. columns mixed) |
| Headings / tables / list items | Expected structures that appear as `#` lines, Markdown tables, `-`/`1.` lines |
| Tokens | Estimated tokens of the Markdown (ASCII characters / 4, other characters / 1.5) |

## Samples (8 files, `data/samples/`)

`report.pdf`, `report.docx`, `paper_two_column.pdf`, `paper_two_column.docx`, `paper_latex.pdf`,
`budget.xlsx`, `deck.pptx`, `scanned.pdf`. They are generated by `scripts/make_samples.py` and
`scripts/make_latex_sample.py` (synthetic text, so the ground truth is exact).

## Caveats (read before quoting any number)

1. **Small, synthetic, and tuned-on.** 8 files that were generated, and the converter was adjusted while
   these were being used. Treat the numbers as proof the pipeline works and as a regression suite,
   not as expected accuracy on arbitrary real documents.
2. **Fairness of the headings comparison.** `markitdown` emits plain text for PDFs and does not try
   to infer headings from font size, so "0/22 headings" reflects a design difference, not a bug.
3. **DOCX is a near tie.** Both tools keep all words in order; the only difference is heading detection on two small files.
4. **OCR sample is a clean synthetic scan.** Real scans will score lower.
5. **No test on real-world PDFs with unusual encodings, forms, or heavy graphics.**

## Not measured

- Token savings versus pasting the original file into any chatbot.
- Quality of AI-written summaries (the code path is unit-tested with a stub model only).
- Speed on large documents.
